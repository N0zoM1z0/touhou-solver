# TH08 Counterexamples CE-0220–CE-0269

## CE-0220: Item ledger retained over-cap Power and sorted away native active order

Date: 2026-07-31

Observed symptom:

- The deterministic item test expected a large Power pickup at Power 124 to
  produce Power 132.
- `ItemPoolState` always selected the lowest free slot and
  `step_item_pool()` updated active items in numeric slot order.
- Full-Power conversion changed only item type, omitting the native velocity
  clamp.

Invalid assumption:

- `add_player_power(+8)` is the terminal native write even when the result
  crosses 128.
- Numeric pool index is the item manager's execution order.
- Converting an active Power item to overflow changes only its value/type and
  cannot affect its later same-frame motion or pickup.

Evidence or trace:

- `add_player_power` at `0x00441850` first performs the integer addition into
  the float Power field;
- small and large pickup branches at `0x00440D5F` and `0x004411D8` call
  `0x00406FA0(128)` immediately after the result reaches or crosses 128;
- allocation at `0x004400BD..0x004401D1` advances a persistent cyclic
  2,096-slot cursor;
- allocation appends at `0x00440413..0x0044043E`, while update starts from
  the active linked-list head at `0x0044051C`; and
- conversion at `0x00441450` changes other active type-0/2 items to type 8
  and, when `vy > -0.5`, writes `(vx, vy) = (0, -0.5)`.

Small deterministic falsifier:

- resources: Power 124;
- item: one collected large Power item;
- old model result: Power 132;
- shipped/native-correct result: Power 128, effective delta 4, full-Power
  conversion enabled.

Ordering falsifier:

- active list `(slot 10 large Power, slot 2 small Power)` at Power 120;
- slot 10 reaches 128 first and converts slot 2 to overflow before slot 2's
  update;
- sorting by slot would process slot 2 first and create a different pickup,
  score, motion, and resource ledger.

Root-cause class: world model / native container and resource semantics.

Correction:

- clamp small/large pickup results to canonical Power 128;
- retain the rotating allocation cursor and explicit active linked-list order;
- reject out-of-range spawns before cursor/RNG mutation; and
- apply the full-Power type and conditional velocity conversion before later
  active-list items update.

Regression test:

- Power 124 plus large Power equals 128, not 132;
- the `(10, 2)` active-order fixture collects large Power then overflow;
- a cursor at 10 allocates slot 10 even when lower slots are free;
- out-of-range spawn preserves cursor and RNG; and
- already-updated versus not-yet-updated converted items retain their
  different same-frame motion outcomes.

Live verification: no game or controller process was run. Shipped
instruction/dataflow semantics are revalidated; the corrected model has
offline implementation authority only.

Status: fixed in the item model, pool recurrence, tests, IDA comments, and
static capability ledger. No collection policy or route-survival authority is
promoted.

## CE-0221: Post-damage Boss threshold overshoot was decoded as the next phase

Date: 2026-07-31

Observed symptom:

- `th08_boss_phase.py` retained only thresholds satisfying
  `0 <= threshold <= current_hp`.
- After a frame's player-shot damage crossed a threshold, telemetry could
  replace the current phase end with a lower retained threshold before the
  native phase transition had run.

Invalid assumption:

- Player-shot HP subtraction occurs before the manager's health/timeout
  transition loop, or the loop reruns after that subtraction in the same
  update.
- A retained threshold greater than current HP belongs to an already-complete
  phase and may be discarded.

Evidence or trace:

- `enemy_manager_update` calls the short-circuit health/timeout transition
  loop at `0x0042CE31`;
- player-shot HP subtraction occurs later at `0x0042D349`;
- `enemy_apply_health_phase_transition` tests strict
  `current_hp < threshold` at `0x0042B50B`; and
- on a match it restores current/phase-start HP to the selected threshold,
  clears that slot, disables timeout, and returns to the manager loop.

Small deterministic falsifier:

- phase-start HP: 1000;
- current HP after player-shot damage: 490;
- retained thresholds: `(500, 100, -1, -1)`;
- old decoded phase end: 100;
- shipped/native-correct current phase end: 500, with a health transition
  pending for the next eligible enemy update.

Root-cause class: world model / native update order.

Correction:

- retain every nonnegative threshold and use the first slot-order crossed
  threshold while pending, otherwise the greatest retained threshold;
- model the exact slot-order health-before-timeout transition prefix;
- expose pending completion separately from a confirmed phase change;
- include all four threshold slots in phase identity; and
- accept signed negative post-damage HP as telemetry rather than rejecting the
  capture.

Regression test:

- the `(490, (500, 100, -1, -1))` fixture reports phase end 500 and pending
  health completion;
- a simultaneously due timeout loses to health and is cleared;
- timeout uses integer elapsed time and restores the largest positive
  threshold;
- multiple crossed thresholds follow native slot order; and
- a bracketed phase-key change inherits only the preceding pending cause when
  gameplay epoch, stage, and Boss pointer continuity also agree.

Live verification: no game or controller process was run. Shipped
instruction/dataflow semantics are revalidated; the corrected projection has
offline/native-semantic authority only.

Status: fixed in the Boss phase adapter, game-neutral progress tracker,
sensing trace, tests, IDA comments, and formal contract. No damage-ranking or
physical phase-compression authority is promoted.

## CE-0222: Boss phase successor operands were treated as unconditional writes

Date: 2026-07-31

Observed symptom:

- The ECL opcode catalog described `0x85` and `0x86` as setting their
  successor subroutine without any engine-mode qualification.
- A first draft of the route-wide Boss configuration atlas consequently
  treated every literal successor operand as an unconditional registry write.

Invalid assumption:

- Executing opcode `0x85` or `0x86` always overwrites the corresponding
  successor register.

Evidence or trace:

- At `0x0041CB70`, opcode `0x85` tests engine flags bit 14 and mode bits
  `7..8`. It always writes the evaluated threshold to `+0x3358[slot]`, but the
  special branch omits the successor write to `+0x3368[slot]`.
- At `0x0041CCFC`, opcode `0x86` uses the same gate. It always writes timeout
  `+0x3378` and resets timer `+0x2E14`, but the special branch omits the
  successor write to `+0x337C`.
- The full successor configuration runs only when:

  ```text
  (engine_flags & 0x4000) == 0
  or ((engine_flags >> 7) & 3) == 0
  ```

Small deterministic falsifier:

- engine flags: `0x4080`;
- prior health successor slot 0: subroutine 12;
- opcode `0x85` operands: slot 0, threshold 1000, successor 44;
- native post-state: threshold 1000, successor remains 12;
- invalid unconditional model post-state: threshold 1000, successor 44.

Root-cause class: world model / omitted native mode gate.

Correction:

- promote opcode `0x84` from inferred to observed after revalidating its timer
  write;
- document the exact `0x85/0x86` engine-mode predicate and retained-successor
  branch in the opcode catalog, IDA, atlas, and contract;
- label every static transition edge as requiring the full-configuration
  branch; and
- deny unconditional runtime successor-registry and phase-sequence authority.

Regression test:

- the opcode catalog test requires observed timer semantics and explicit
  conditional successor descriptions;
- the atlas test requires the exact engine-mode predicate on all checked
  transition edges; and
- retained report regeneration is exact.

Live verification: no game or controller process was run. Retained normal
gameplay engine flags corroborate the full-configuration side of the
predicate, but no ECL write is runtime-bracketed.

Status: fixed in the opcode catalog, generated catalog reports, Boss
configuration atlas, tests, IDA comments, and contract. No phase-route,
damage-benefit, or action authority is promoted.
