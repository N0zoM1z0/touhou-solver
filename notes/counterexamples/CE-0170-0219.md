# TH08 Counterexamples CE-0170–CE-0219

## CE-0170: Exact cross-epoch event replay still missed physical delivery and survival gates

Date: 2026-07-29

Observed symptom:

- Schema-v6 Stage-5 run `20260729_104222` passed exact program identity across
  accepted epoch 0 and observation epoch 2.
- All 127 batches and 3,384 requests independently replayed complete with
  zero unknown; online preparation was `0.121 ms`.
- Event derive, replay compact, and previous synchronous emit p95 were
  `0.620/0.564/2.862 ms`, failing fixed `0.500/0.500/1.000 ms` limits.
- The run also took 11 hits: nonspell/103/107/111/115 =
  `4/0/1/4/2`, one above the user-set maximum.

Invalid assumption:

- Removing full-program bind cost and fixing epoch identity is sufficient to
  make the existing verbose evidence representation physically deliverable.
- Repeating null-record dictionaries and full derivation JSON is necessary
  for independent replay.

Evidence or trace:

- code checkpoint `fcc37ec`;
- raw trace SHA-256
  `365aaee1c9a328b45b538510536bb5736a0ed66f699058e50b93a6a80882eee4`;
- strict failed report SHA-256
  `3738d329d1921932b0688223f044d4666f29825e72023b9ee43cb03ee76cb24b`;
- result note
  `notes/research/g5/G5_AUXILIARY_LITERAL_FIRE_CYCLE_RUNTIME_DELIVERY_V3_STAGE5_FAILURE_20260729.md`.

Root-cause class: control/runtime evidence materialization and delivery;
survival remains a separate planner/workload failure.

Correction:

- retain V3 as the first observed cross-epoch semantic delivery but reject
  physical delivery authority;
- project only usable records with exact source indices while proving omitted
  records null through the native status histogram;
- retain every raw replay byte and replace repeated derived results with
  independently reconstructed canonical commitments;
- decode only the timer state consumed by the literal proxy; and
- keep every timing, cadence, hard no-Bomb, cleanup, and survival threshold
  unchanged under a separately fixed V4 contract.

Regression test:

- projection rejects omitted non-null status, duplicate/out-of-range source
  indices, raw/hash/bundle mismatch, and result-commitment tampering;
- independent raw-byte replay and LRU simulation remain exact;
- retained replay crosses at least three observation epochs and meets the new
  isolated line-size/serialization gates;
- V1/V2/V3 reports remain immutable.

Live verification: V3 failed as observed. V4 requires a fresh focused
physical run and two consecutive Stage-5 runs at no more than ten hits before
handoff.

Status: observed physical counterexample; V3 semantic epoch correction
accepted as evidence, delivery/survival rejected, V4 fixed before
implementation.

## CE-0171: Foreground loss contaminated the first schema-v7 attempt

Date: 2026-07-29

Observed symptom:

- The first checkpoint-`5fae77a` Stage-5 attempt armed correctly and reached
  frame 2,736, then the foreground guard observed a non-TH08 foreground PID.
- The controller immediately raised
  `TH08 lost foreground; refusing to send or retain keys`.
- The attempt ended before spell 107 with one nonspell hit and zero auxiliary
  batches. The supervisor retained a failed session and completed exact
  process/input cleanup.

Invalid assumption:

- A successfully focused and armed unattended launch will retain foreground
  for the complete physical route.
- A partial low-hit attempt can be counted as a V4 delivery or survival pass.

Evidence or trace:

- run note
  `notes/runs/lunatic_route2_stage5_unattended_20260729_112743.md`;

  `94f3a68306f230a96341311f474c8d4f1e9f577aaa2e26653cfe32cd79c47114`;
- normalized session SHA-256
  `9ea76db56ccf43fcc55c544a095b0c4fd449652b7075f8e82f7c06fd52662a5f`.

Root-cause class: control/runtime external foreground contamination.

Correction:

- keep the hard foreground guard, fail-closed key release, exact cleanup, and
  failed-run retention;
- exclude the attempt from delivery and consecutive survival counts; and
- retry the unchanged checkpoint only after verifying no residual process
  and valid executable identity.

Regression test:

  and verify release/cleanup on error;
- a completed physical run must retain foreground until route completion.

Live verification: pending an uncontaminated rerun.

Status: observed external contamination; controller fail-closed behavior
accepted, run excluded from V4 and survival acceptance.

## CE-0173: Columnar rows remained a separate synchronous publication

Date: 2026-07-29

Observed symptom:

- Completed schema-v8 Stage-5 run `20260729_120859` independently replayed
  all 4,238 requests with zero unknown and passed schema, program identity,
  preparation, cache, oracle, line-size, event-derive, total, cadence,
  no-Bomb, completion, and cleanup gates.
- Physical line p95/max was only `14899/15453` bytes, but previous separate
  synchronous emit p95 was `1.412 ms`, above the fixed 1.000-ms limit.
  Replay-compact p95/max was `0.507/8.452 ms`, just/strongly above its fixed
  limits.
- The run took 14 hits: nonspell/103/107/111/115 = `5/1/5/2/1`.

Invalid assumption:

- Reducing one separately emitted UNC trace row below 16 KiB would remove its
  fixed write cost.
- Continued field-level JSON compaction was necessarily the correct next
  delivery optimization.
- One earlier ten-hit observation established survival stability for an
  action-neutral observer.

Evidence or trace:

- code checkpoint `35d3163`;
- raw trace SHA-256
  `4f2505ff84753e07fa5bf827dc71f770c8190e4aafc01e536819d87b23d50088`;

  `1c3018c4831063bd645594856c7e5dc3384e4fd50a54f35b06f5da764d922d6e`;

separate planner/workload failure.

Correction:

Status: observed physical counterexample; V5 semantics/line size accepted,
