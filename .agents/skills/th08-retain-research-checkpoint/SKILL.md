# Retain A TH08 Research Checkpoint

Turn one verified result into compact, navigable evidence without committing
raw captures, unrelated user inputs, or unsupported authority claims.

## Establish What The Result Proves

1. Read `AGENTS.md`, `START_HERE.md`, `STRATEGY.md`, the governing contract,
   the result artifacts, and the current daily/counterexample shards.
2. Label every material conclusion observed, inferred, or hypothesized.
3. State exact code and physical-code checkpoints, workload and immutable
   versions, acceptance/rejection gates, contamination, cleanup, and limits.
4. Reconcile any document disagreement against code and retained evidence
   before editing authority sources.

## Retain Compact Evidence

1. Keep raw JSONL and launch logs local and ignored; hash them and record
   retention status. Do not remove an older replay bundle until `AGENTS.md`
   permits it.
2. Generate or verify the contract-specific compact report, dossier,
   comparison, deaths/phase summary, and deterministic audit.
3. Regenerate important reports from raw input and compare bytes or SHA-256
   when the contract requires reproducibility.
4. Preserve failed reports as failed. Never relabel an invalid comparator,
   timeout, incomplete proof, or contaminated run as accepted.

## Align Sources Of Truth

1. Update the relevant run note and result/contract note.
2. Route a concrete failure to the current shard named by
   `notes/COUNTEREXAMPLES.md`; route chronology to the daily shard named by
   `notes/RESEARCH_LOG.md`.
3. Update affected research indexes, `STRATEGY.md`, the consolidated roadmap,
   and `START_HERE.md`. Keep `START_HERE.md` short enough to remain a useful
   volatile handoff.
4. Record the exact next gate, controls, stopping rule, raw-retention
   requirement, and commands by reference to their canonical source.

## Verify And Commit

1. Run the smallest relevant tests and integrity checks for changed code or
   generated evidence. Do not rerun physical gameplay merely to test this
   skill.
2. Verify no TH08, controller, supervisor, or test process remains alive.
3. Inspect the staged set explicitly. Never stage `audits/`, raw JSONL,
   launch logs, screenshots, executables, credentials, caches, or native
   build output.
4. Run the staged diff whitespace check and verify recorded artifact hashes.
5. Create one focused English commit. Report the commit, evidence outcome,
   validation, remaining untracked user inputs, and exact next action.
