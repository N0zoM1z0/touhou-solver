# TH08 Danmaku System

Status: the load, scheduling, phase-transition, direct bullet/laser emission,
and per-frame projectile pipeline is structurally parsed. The static analyzer
resolves every spell phase on the three pinned Sakuya/Remilia acceptance
routes; exact full-engine runtime parity remains ongoing.

## Evidence Conventions

- **Observed**: directly established by executable code, decoded file bytes, or
  a reproducible local parser result.
- **Inferred**: the strongest current interpretation of observed formulas or
  state changes, but not yet confirmed by controlled gameplay observation.
- **Unknown**: not established strongly enough to rely on.

No online format documentation, third-party extractor, ECL decompiler, or
opcode table was used.

## End-to-End Model

The normal stage danmaku path is:

1. The stage bootstrap registers ordered 60 Hz update systems.
2. The enemy manager selects and loads one stage ECL resource.
3. The archive loader extracts the resource from `th08.dat` and removes its
   `edz?` wrapper.
4. The ECL loader relocates stage-timeline and enemy-subroutine offsets.
5. Each active stage timeline emits scheduled events, primarily enemy spawns.
6. Each spawned enemy starts one ECL subroutine in its private VM state.
7. The enemy VM executes all due instructions for the current tick.
8. Enemy-end, health-threshold, timeout, and interrupt transitions replace or
   nest ECL subroutines as phases advance.
9. ECL opcodes `0x60..0x68` build a bullet-emission descriptor, while
   `0x72/0x73` create lasers.
10. The pattern emitter expands bullet descriptors into individual slots.
11. The bullet and laser managers advance phase, transformation, velocity,
    position, culling, and animation every frame.

This means the visible pattern is not stored as a list of bullet coordinates.
It is generated by a stage timeline choosing enemy scripts, then by those
scripts repeatedly executing parameterized emission instructions.

## Player Frame Adapter Boundary

**Observed** in the priority-9 player callback and route-2 Bomb callbacks:

- Normal initialization starts at `(192,384)`, player state 1, shared state
  timer 120, focus sentinel 2, and four option records in enter state.
- Spawn transition and the state-3 decrement occur before the same frame's
  movement eligibility test.
- Bomb selection reads the previous focus byte before current input/focus
  processing. Its callback executes at local timer 0 before movement.
- Route-2 movement axis scales are Sakuya `0.5`; Remilia normal `0 -> 2` at
  local frame 60; Remilia Last Spell `0 -> 3` at local frame 60; Dissolve `0`.
- Position and velocity fields are binary32 stores. Store-boundary rounding is
  part of replay fidelity, not a display concern.

`scripts/th08_route2_player_runtime.py` implements this subset. The separate
`scripts/th08_simulator.py` now runs replay publication and this player subset
at their recovered schedule positions. `scripts/th08_replay_player_projection.py`
uses that executor and deliberately requires accepted Bomb starts as explicit
events, because replay input alone does not encode hit/Last-Spell state or
item-restored Bomb stock. `scripts/state_trace.py` can capture selected fields
after each event using raw binary32/binary64 encodings and identify the first
game-versus-simulator mismatch.

## Archive and Resource Decode

**Observed**:

- `th08.dat` starts with `PBGZ` and contains 317 directory entries.
- `pbgz_archive_parse` (`0x00474CE0`) decodes and decompresses its directory.
- Member data uses a custom MSB-first LZSS stream implemented at
  `pbgz_lzss_decompress` (`0x004740E0`).
- ECL and STD members carry a four-byte `edz?` wrapper.
- `decode_edz_resource` (`0x0043E390`) selects one of eight parameter tuples
  and calls the same XOR/shuffle primitive used for the PBGZ directory.
- ECL files use marker `E`; after wrapper removal the first dword is `0x800`.

Reproducible tools:

- `scripts/th08_pbgz.py`
- `scripts/th08_resource.py`

All 24 ECL and 18 STD resources were extracted and decoded with exact declared
output sizes.

## ECL File Layout

**Observed** from `ecl_load_file`, accessors at `0x0042DFB0` / `0x0042DFD0`,
and every decoded ECL file:

```c
struct Th08EclFileHeader {
    uint32_t magic_0x800;                 // +0x00
    uint16_t subroutine_count;            // +0x04
    uint16_t timeline_count;              // +0x06
    uint32_t timeline_or_end_offsets[16]; // +0x08
    uint32_t subroutine_offsets[];         // +0x48
};
```

- The first `timeline_count` slots are stage-timeline starts.
- Slot `timeline_count` is the data-end/file-size sentinel. This explains why
  decoded files have exactly one more nonzero timeline-table value than the
  count.
- The loader relocates all 16 timeline slots and all `subroutine_count`
  subroutine offsets in place.
- Subroutines precede timelines in every decoded file.

### Stage Timeline Record

**Observed** in `stage_timeline_step` (`0x0042A8A0`):

```c
struct Th08EclTimelineInstruction {
    int32_t time;            // +0x00; negative stops this timeline
    uint16_t opcode;         // +0x04; observed 0x00..0x10
    uint8_t size;            // +0x06; byte distance to next record
    uint8_t difficulty_mask; // +0x07
    uint32_t arguments[];    // +0x08
};
```

- The enemy manager keeps one current pointer for each timeline and calls the
  scheduler every update.
- All records due at the current stage time are handled in one call.
- A record executes only if its mask intersects the active timeline
  difficulty mask.
- Opcodes `0`, `1`, and `0x0F` spawn an enemy at explicit `(x,y)`.
- Opcodes `2`/`4` choose random x inside a supplied range.
- Opcodes `3`/`5` choose random x across the 384-unit playfield.
- Opcodes `0x0B`/`0x0C` spawn an enemy and set two additional enemy fields.
- Opcode `0x0A` can hold the timeline while a referenced enemy remains active.

Some non-spawn opcode names in the generated listing are intentionally
conservative until their downstream subsystems are fully named.

### Enemy Subroutine Record

**Observed** in `enemy_ecl_vm_step` (`0x004184B0`):

```c
struct Th08EclInstruction {
    int32_t time;            // +0x00
    uint16_t opcode;         // +0x04; observed 0x00..0xB8
    uint16_t size;           // +0x06
    uint8_t field_08;        // +0x08; purpose not yet established
    uint8_t difficulty_mask; // +0x09
    uint16_t parameter_mask; // +0x0A
    uint32_t arguments[];    // +0x0C
};
```

- Opcode `1` terminates the enemy script.
- Opcode `0` is legal and falls through the VM default path.
- Each subregion ends with the 12-byte footer
  `{time=-1, opcode=0xFFFF, size=12, ...}`.
- The parameter mask selects arguments that must be evaluated as VM variables
  instead of used as literal words/floats.
- `ecl_start_subroutine` (`0x00418450`) installs a relocated subroutine
  pointer in an enemy's VM state.
- Subroutine instructions use a stricter mask predicate than timeline records:
  all active difficulty/rank bits must be included in the record mask.
- Integer VM variable `10040` reads `g_difficulty_index`; variable `10052`
  reads `g_player_route_id`. The route manifests use these two observed
  mappings to fold known branches.

`enemy_spawn_from_timeline` (`0x0042A4E0`) scans 480 enemy slots, each
`0x53D0` bytes, copies the enemy template, stores the timeline position,
starts the chosen subroutine, and runs the VM once immediately.

### Phase And Interrupt Control Flow

**Observed** in `enemy_ecl_vm_step`, `enemy_manager_update`,
`enemy_apply_health_phase_transition` (`0x0042B490`), and
`enemy_apply_timeout_phase_transition` (`0x0042B930`):

| Opcode | Runtime state | Transition |
| --- | --- | --- |
| `0x34` | current VM call frame | Direct subroutine call |
| `0x7D` | interrupt slot index | Save the 0x228-byte VM frame and invoke the installed slot |
| `0x7E` | `int16 sub_ids[32]` at `enemy+0x2CF0` | Install `(sub_id, slot)` |
| `0x82` | `int16` at `enemy+0x2CEE` | Subroutine started when the enemy/current phase ends |
| `0x85` | thresholds at `+0x3358`, sub IDs at `+0x3368` | Start indexed sub when HP crosses threshold |
| `0x86` | timeout at `+0x3378`, sub ID at `+0x337C` | Start sub when the phase timer reaches timeout |
| `0x87` | one of auxiliary VM slots | Start a concurrent/auxiliary subroutine |
| `0x99` | copies `+0x2CEE` to `+0x337C` | Reuse enemy-end sub as timeout transition |

The health transition raises current HP to the crossed threshold before
starting its associated sub. The timeout transition tests the phase timer,
starts `+0x337C`, and clears phase/spell state. These are direct code
observations, not spell-order guesses.

`scripts/th08_ecl_flow.py` constructs conservative inter- and intra-subroutine
control flow from these operations plus jumps, calls, child spawns, and
timeline roots. Unknown comparisons retain both successors. Known difficulty
and route comparisons are folded.

For each reachable spell-start instruction, `scripts/th08_route_manifest.py`
traverses calls, child spawns, interrupt handlers, and auxiliary VMs as members
of the same phase component. Enemy-end, health-threshold, and timeout edges are
reported as phase exits and are not traversed into the component. Each manifest
entry records the component subroutines and edges plus per-subroutine counts of
direct bullet emission, transform definition, laser spawn, and built-in
callback operations.

### Enemy Motion And Clear Opcodes

**Observed** for ECL opcode `0xB2` at the VM dispatch site `0x00419FF6` and
native handler `ecl_set_random_player_biased_motion` (`0x004224A0`):

- Arguments are `duration`, `easing_mode`, and `speed`. The four corpus uses
  occur in the stage-4A normal/spell resources and reduce to `(80,0,1.2)` and
  `(120,0,1.0)`.
- The handler consumes `rng.next_mod(4)` plus one angle sample. Selector zero
  samples a signed angle in `[-pi,pi)`; the other three selectors choose a
  left/right cone biased toward player x.
- Horizontal direction uses the shortest path on a 384-unit periodic span.
  At ties it chooses the wrapped direction. Angles pointing out of the upper
  or lower 48-unit movement margin are vertically reflected.
- Positive duration calls `enemy_start_timed_polar_displacement`
  (`0x004222B0`), storing displacement as
  `(cos(angle),sin(angle))*speed*duration`. Non-positive duration installs
  constant polar velocity.
- `enemy_motion_update` (`0x00422C40`) evaluates state 2. Easing modes 0/7 are
  linear, 1/2/3 are ease-in quadratic/cubic/quartic, and 4/5/6 are ease-out
  quadratic/cubic/quartic. Expiry snaps to the exact stored destination and
  clears velocity/movement state.

The reusable IR and TH08 adapter are executable in `scripts/pattern_ir.py` and
`scripts/th08_enemy_movement_model.py`. The formulas are statically observed;
frame-by-frame x87/binary32 parity still requires a runtime differential trace.

**Observed** for opcode `0x5F`: the VM calls
`enemy_manager_clear_active_with_score_items` (`0x0042EFB0`) with popup cap
8000. It removes every eligible active enemy, invokes configured end
subroutines, and spawns type-6 scaled-score items for primary flag `0x80`, with
the displayed/reward value rising by 30 up to the cap.

**Observed state mutation, inferred domain name** for opcode `0xB8`:
`spell_state_set_end_transition_flag` (`0x0041F0E0`) assigns bit `0x800` in
`g_spell_card_state`. All 82 shipped occurrences write 1 at time zero in
spell-ending enemy subroutines; spell-card start and finish clear the bit.
`set_spell_end_transition_flag` is therefore contextual terminology rather
than an independently observed UI/gameplay label.

**Observed** for opcode `0x53`: enemy flags2 bit `0x2` is the boss flag. The
enemy update reads it for boss-specific damage scaling, tracked boss position,
health-ratio and bottom-marker publication, and boss-defeat projectile/enemy
cleanup. The 195 corpus uses contain 190 writes of 1 and five later writes of
0. `set_boss_flag` replaces the earlier opaque flag name.

**Observed** for opcode `0x81`: flags bits 20..22 select the health-zero defeat
mode, not a render mode. The corpus uses only values 0..3. The switch in
`enemy_manager_update` (`0x0042D6AF`) selects different deactivation, score,
cleanup, effect, phase, and player-state outcomes. A deterministic simulator
must retain this selector across health-zero transitions.

**Observed, presentation-only** for opcode `0x91`: flag `0x02000000` causes
`enemy_manager_render` (`0x0042E140`) to reapply saved ANM script IDs through
`anm_vm_set_script` (`0x0040EC00`) for the main sprite and trail nodes. All 107
corpus uses write 1. There is no consumer in movement or collision, so this
flag belongs in a visual validator but not the route-search state.

**Observed** for opcode `0xAF`: `g_timeline_enemy_spawn_suppressed` is tested
by timeline spawn record types 0..5 and 0xB/0xC. Nonzero consumes the scheduled
record without calling `enemy_spawn_from_timeline`; zero permits the spawn.
Stage 2 uses the sequence `0,1,0,1,0`. The neutral
`SetTimelineSpawnEnabled` event and inverted TH08 lowering are in
`scripts/pattern_ir.py` and `scripts/th08_pattern_adapter.py`.

**Observed write and static relevance boundary** for opcode `0x93`: it writes
`g_ecl_write_only_marker` at `0x004EA290`. IDA has one direct xref, the writer,
and no direct executable reader. It is excluded from search state but retained
as validator telemetry until a runtime watchpoint confirms there is no indirect
aliasing; no phase/display noun is assigned from its values alone.

**Observed** for opcode `0xAD`: enemy bit `0x40000000` gates the full
VM/movement/phase/damage update block. When the bit is set, an active player
Bomb or nonzero global player-transition state skips that enemy's block;
otherwise it runs. Opcode `0xB0` also enables this bit, defeat mode 3 clears it,
and the player death/deathbomb transition clears it across indexed enemies.

**Observed** for opcode `0xB7`: enemy bit `0x80000000` is narrower Bomb damage
immunity. While the player Bomb-active field is set, the enemy's player-shot
and hurtbox damage block is skipped; outside Bomb it remains damageable. The
corpus uses both 0 and 1, and defeat mode 3 clears the bit. Both `0xAD` and
`0xB7` are solver-relevant because they change motion and/or phase damage
timelines.

### Spell Reward, Trail, And Render-State Opcodes

**Observed** for opcode `0x9B`: enemy flag `0x08000000` selects a fixed spell
reward path. `spell_card_start` (`0x004153B7`) initializes the working bonus to
99,999,990 instead of the payload score, `spell_card_update` (`0x00416CDB`)
skips normal per-frame decay, and `spell_card_finish` (`0x0041629D`) stores
capture-result field 700 instead of the time-derived 100..1000 value. All 19
corpus uses enable it and occur on the shipped special/time-survival spell
sequences. The opcode also writes 99,999,990 to
`g_fixed_spell_reward_write_sentinel`, which has no direct executable reader.

**Observed** for opcode `0x9D`: the four arguments are `(mode,
history_samples, collision_sample_limit, render_stride)` and are stored at
enemy offsets `+0x534C..+0x5352`. A nonzero mode shifts 28-byte position/ANM
history records each enemy update. The renderer consumes mode bit `0x08` for
strip geometry, `0x02` for taper/interpolation behavior, and `0x04` for alpha
fade. More importantly, `enemy_test_player_contact_at_position`
(`0x0042C290`) can repeat collision/graze tests at historical indices
`1,7,13,...` below `collision_sample_limit`; mode bit `0x02` interpolates those
positions. The 22 shipped records use only `(5,15,0,1)`, `(0,15,0,1)`, and
`(5,90,0,6)`, so their historical collision is disabled. The neutral
`HistoricalHitboxTrail` and TH08 lowering preserve nonzero future cases while
excluding shipped visual-only history from search hashes.

### Enemy-Body Lethal AABB

**Observed** in `enemy_manager_update` (`0x0042C660`): every active enemy whose
flags at `+0x3324` have contact bit `0x04` set reaches the body-contact consumer
at `0x0042CF7A`, unless one of the surrounding invulnerability/disabled-state
guards excludes the whole damage block. The consumer passes position
`enemy+0x2D88` and contact size `enemy+0x2D70` to
`enemy_test_player_contact_at_position` (`0x0042C290`).

That helper scales the contact-size vector by 1.5, then calls
`player_test_deadly_aabb_contact` (`0x0044A360`) with the global player state.
The latter constructs a hazard rectangle as `center +/- scaled_size/2`, tests
it against the player's live lethal rectangle at player offsets
`+0x38C/+0x390/+0x398/+0x39C`, and calls `player_dead_handler` on overlap while
the player is in normal phase 0. Therefore the planner-visible enemy half
extents are exactly `0.75 * enemy_contact_size`; `+0x2D70` stores full size,
not half size.

This is a separate hazard family from bullets and lasers. The Stage-3
no-Bomb practice run hit at frame 4,885 during spell 35 with zero bullets and
zero lasers, positive projectile-model clearance, and a live spell owner at
`0x5826C0`. Static control flow makes enemy-body contact the strong candidate,
but the baseline trace did not capture the owner's position/size/flags at that
frame. The sensor first captured the spell owner, then Stage-5 CE-0059 proved
that nonspell and simultaneous enemies cannot be omitted. It now scans all 480
fixed slots and captures the native player lethal rectangle plus every enabled
enemy AABB in one stable manager-frame epoch on each new hit edge.

**Observed motion-layout correction:** `sub_42DEB0` (`0x0042DEB0`) integrates
the vector at enemy `+0x2D4C` into the internal component at `+0x2D34`.
The update path later composes world collision/render position `+0x2D88` with
other relative/scripted motion. Thus `+0x2D4C` is not generally the derivative
of `+0x2D88`. Stage-4A pointer `0x00597600` retained world `y=164` while the
second `+0x2D4C` float increased from `18.512` to `146.910`, providing runtime
proof. Planner world motion is now estimated from consecutive `+0x2D88`
observations; the internal vector remains diagnostic evidence.

**Observed, presentation-only** for opcode `0x9F`: enemy byte `+0x332F`
selects one of four linked render lists. `enemy_manager_render` consumes layers
0/1 in its early wrapper and 2/3 in its late wrapper. The 38 shipped writes use
only layers 0, 1, and 3.

**Observed, presentation-only** for opcode `0xB6`: flags2 bit `0x100` changes
both secondary enemy ANM slots from their per-slot local anchor to the shared
enemy anchor at `+0x294`. All 30 shipped uses enable it; the only consumers are
in `enemy_manager_render`.

**Observed, presentation-only** for opcodes `0xB3..0xB5`: they operate the
stage-background auxiliary ANM sequence. `0xB3` initializes it from ANM file
slot 2 and the current sequence-state script; `0xB4` clears its enable byte;
`0xB5`, while state is below 12, plays sound 45, increments the state, reloads
that script, and selects intermediate mode 1 or final mode 2. The corpus uses
`0xB3` twice and `0xB5` eight times; it never emits `0xB4`, whose handler is
nevertheless directly observed.

## Bullet Emission

### ECL Opcodes 0x60 Through 0x68

**Observed** in `enemy_ecl_emit_bullets` (`0x00422720`): all nine opcodes use
the same 44-byte instruction layout. `opcode - 0x60` becomes emission mode
`0..8`.

```c
struct Th08EclBulletEmissionArgs {
    uint16_t bullet_type;       // arg0 low half
    uint16_t color;             // arg0 high half
    int32_t count_1;            // arg1
    int32_t count_2;            // arg2
    float speed_1;              // arg3
    float speed_2;              // arg4
    float angle_1;              // arg5
    float angle_2;              // arg6
    uint32_t transform_flags;   // arg7
};
```

Parameter-mask mapping is exact:

| Bit | Dynamic value |
| --- | --- |
| `0x01` | bullet type |
| `0x02` | color |
| `0x04` | count 1 |
| `0x08` | count 2 |
| `0x10` | speed 1 |
| `0x20` | speed 2 |
| `0x40` | angle 1 |
| `0x80` | angle 2 |

The parser renders these as `$i16(...)`, `$i32(...)`, or `$f(...)`; it does
not mislabel a VM variable number as a literal pattern parameter.

The enemy's current transformed position becomes the emission origin. The
game also applies difficulty/rank interpolation to the two counts and speeds
before expansion.

### Pattern Expansion

**Observed formulas** in `bullet_emitter_spawn_pattern` (`0x00430E10`) and
`bullet_pool_spawn_one` (`0x0042F5F0`):

- The emitter nests `count_2` outer iterations and `count_1` inner iterations.
- Each iteration allocates one of 1536 bullet slots, stride `0x10B8`.
- Modes `0`/`1` use an alternating symmetric fan offset. Mode 0 adds the
  player-aim angle; mode 1 does not.
- Modes `2`/`3` distribute shots by `2*pi/count_1`, with an outer-layer angle
  increment. Mode 2 adds player aim; mode 3 does not.
- Modes `4`/`5` use the same ring spacing with an extra half-step
  `pi/count_1`. Mode 4 adds player aim; mode 5 does not.
- Mode `6` randomizes angle inside the two supplied angle bounds.
- Mode `7` randomizes speed inside the two speed bounds and uses ring angles.
- Mode `8` randomizes both angle and speed.

**Inferred terminology**: “fan”, “ring”, “aimed”, and “absolute” are names for
the observed formulas. Static analysis proves the arithmetic and the call to
`angle_to_player` (`0x0044C1B0`); a controlled visual replay has not yet been
used to assign canonical pattern names.

The allocated bullet stores its origin, speed, angle, velocity, state, original
flags, active transformation flags, and up to 18 queued 24-byte transformation
records.

### Pattern And Transform Sounds

**Observed** for ECL opcode `0x71`:

- Argument 0 below zero clears descriptor flag `0x200`. Otherwise it stores a
  pattern sound ID and enables the flag. After all bullets have been expanded,
  `bullet_emitter_spawn_pattern` queues that sound with pan derived from the
  emission-origin x coordinate.
- Argument 1 is copied through descriptor `+0x204` to every bullet at `+0xDC8`.
  When a queued transform activates and the bullet's sound gate at `+0xDCC` is
  enabled, a nonnegative value is played as the transform-activation sound.
- The acceptance routes normally use `(-1, -1)`. Extra derived-pattern subs
  127 and 141 use `(15, -1)`, changing only the pattern emission sound.

### Transform Record

**Observed** record layout:

```c
struct Th08BulletTransformRecord {
    float float_0;                 // +0x00; meaning depends on kind
    float float_1;                 // +0x04; meaning depends on kind
    int32_t int_0;                 // +0x08; meaning depends on kind
    int32_t int_1;                 // +0x0C; meaning depends on kind
    uint32_t kind;                 // +0x10; one active transform bit
    uint32_t wait_for_active_clear;// +0x14
};
```

There are 18 records per bullet. `kind == 0` terminates the queue. A record is
eligible only when its kind occurs in the emission's original transform flags;
`wait_for_active_clear == 0` delays it until existing active transforms clear.

**Observed** in `bullet_apply_next_transform` (`0x0042FFC0`):

- `+0xDCC` is the index of the next unconsumed record. The executor forms
  `bullet + 0xDD0 + 24 * queue_cursor` at `0x00430001`.
- Ineligible and immediate records advance the cursor and continue scanning.
  A record that installs an active handler advances the cursor before the
  executor returns. The record at the cursor is therefore not the currently
  active stop record.
- The active 0x40/0x80/0x100 record has already been consumed. Its live
  operands and repeat progress must be read from `+0x1010..+0x102C`, while
  `+0xDCC/+0xDD0` describe later work.

The behavior-neutral live trace retains the historical eight bullet fields
unchanged and appends one optional compact runtime payload:

```text
[speed, angle, original_flags, queue_cursor, next_record,
 timer_fraction, timer_elapsed, duration, resume_speed, angle_operand,
 repeat_limit, repeat_count, callback_phase, callback_aux,
 velocity_changes, trajectory_uncertainty_x, trajectory_uncertainty_y]
```

`next_record` uses
`[index, kind, allow_while_active, float_0, float_1, int_0, int_1]`.
The payload is present only when active/original flags or a nonzero pending
record establish transform relevance. **Inferred design boundary:** decoding
this TH08-native state is observational; neither local nor global planning may
change until a native same-slot differential validates its frame semantics.

Normal traces attach the payload only to player-nearby bullets. The explicit
`--trace-transform-runtime` diagnostic adds a separate `transform_bullets`
list containing transform-relevant records from the complete pool. It is
opt-in because it increases raw capture size and is evidence instrumentation,
not a gameplay sensor required by the planner. The compact
`scripts/analysis/th08_transform_trace.py` report hashes the raw source and
retains coverage
plus adjacent same-slot lifecycle changes.

### Tagged Callback Velocity Toggles

Spell 111 established a second motion mechanism that is independent of the
18-record transform queue.

**Observed in decoded `ecldata5` sub 63**:

- At local time 350, the VM sets tag mask `0x00100000`, callback angle
  `2.356194`, callback speed zero, then invokes callback 12.
- At local time 450 it sets the same tag mask and invokes callback 12 again.
- At local time 710 opcode `0x04` sets VM time to 350 and applies displacement
  `-280`, targeting instruction `0x6ED0`. The stop/resume schedule therefore
  repeats every 360 local updates.

**Observed in callback 12 at `0x00424A20`**:

- Ignore inactive bullets and bullets for which

## Per-Frame Bullet Runtime

**Observed** in `bullet_manager_update` (`0x00431240`):

- Visit slot 0 first, then slots 1535 down through 1. Allocation uses a
  separate wrapping cursor, so allocation order must not be substituted for
  update/collision scan order.
- Advance spawn states 1 through 5.
- Call `bullet_apply_next_transform` (`0x0042FFC0`).
- Run handlers selected by active transformation bits.
- Unless paused by state, add velocity to position.
- Apply playfield/offscreen lifetime checks and animation updates.

All transform kinds present in the decoded ECL corpus now have observed field
semantics. For `0x1000000`, the first record maps `float_0/float_1` to child
angles and `int_1` low 16 bits to count 1. Packed `int_0` is:

```text

bits 24..30  emission mode
bits 16..23  child bullet type
bits 8..15   child color
bits 0..7    child transform-program start index
```

## Laser Runtime

**Observed** in the laser spawn and manager update paths:

- Pool capacity: 256 slots, stride `0x59C` (1436 bytes).
- ECL `0x72` uses an absolute angle; `0x73` adds the player-aim angle.
- Arguments are packed type/color, angle, speed, tail, head, maximum length,
  width, warmup frames, active frames, fade frames, collision-enable frame,
  collision-disable frame, and flags.
- The update advances `head += speed * time_scale`, clamps
  `head - tail <= maximum_length`, and keeps `tail >= 0`.
- Runtime phases are warmup, active, and fade; width/alpha ramp behavior is
  selected by a flag, and collision is gated by the two collision frame
  thresholds.
- Collision constructs a horizontal rectangle in laser-local coordinates. Its
  center is `origin + (tail + (head-tail)/2, 0)`. Full collision length is
  `head-tail` while `tail==0`, and `0.7*(head-tail)` after the tail becomes
  positive. The transverse size passed to the player test is half the
  descriptor width. The player test then divides the incoming size vector by
  two, so active lethal transverse half-extent is one quarter of descriptor
  width before combining it with the player's SHT half extents.
- For non-alpha warmup and fade, the manager overwrites the longitudinal
  rectangle size with half the ramped/fading width before the phase collision
  gate. An allocated warning/fading record is therefore not always a lethal
  full `tail..head` segment.
- The player center is inverse-rotated by `-angle` around the laser origin, then
  the game performs an inclusive AABB overlap using the player's SHT hitbox
  half extents. A graze check expands each laser-local rectangle boundary by
  48 units.
- Warmup collision starts at `timer >= collision_enable_frame` without graze.
  Active collision runs every update and enables graze only when
  `timer % 20 == 0`. Fade collision continues while
  `timer < collision_disable_frame`, again without graze.
- Phase transitions fall through in the same manager call. A warmup completion
  can therefore run both warmup and active collision, and an active completion
  can run both active and fade collision. Tail distance `>=640` deactivates the
  laser.

Recovered runtime offsets:

| Offset | Meaning |
| ---: | --- |
| `+0x548..+0x550` | origin x/y/z |
| `+0x554` | angle |
| `+0x558/+0x55C` | tail/head distance |
| `+0x560` | maximum length |
| `+0x564/+0x568` | target/current width |
| `+0x56C` | speed |
| `+0x570..+0x580` | warmup/collision-enable/active/fade/collision-disable frames |
| `+0x584` | allocated/active |
| `+0x588..+0x593` | `Th08Timer`; fraction `+0x58C`, integer current `+0x590` |
| `+0x594/+0x596` | flags and packed type/color |
| `+0x598/+0x599` | phase and collision/graze byte |

IDA Local Types contains the verified 1436-byte `Th08Laser` layout.
`scripts/th08_laser_model.py` implements the observed kinematics, phase
fallthrough, collision schedule, active/warmup/fade rotated hit geometry, flag
selected alpha/width ramps, and graze expansion. The live adapter lowers each
future collision call into a game-neutral time-indexed segment trajectory.
Future ECL-driven origin/angle mutations remain dependent on the executable
ECL oracle and are not yet phase-exact.

## Registered Frame Order

**Observed** in `update_chain_insert` (`0x0043C880`),
`update_chain_execute` (`0x0043CA50`), and `game_frame_pump_60hz`
(`0x00441E70`): update nodes are inserted in ascending 16-bit priority and the
`<=` traversal preserves registration order for equal priorities. The frame
pump advances in 1/60-second quanta, executes the update chain, and later runs
the separately ordered render chain when a presentation frame is due.

The solver-critical registered order is priority 2 gameplay controller,
optional replay input at 6, replay RNG synchronization at 7, stage background
at 8, player at 9, enemy manager at 11, spell-card manager at 12, an
as-yet-unnamed callback at 13, and bullet manager at 14. Recording captures
input at 17; playback has a post-update callback at 18.

**Observed internal order**:

- `player_update` runs its projectile pool, deathbomb/death transition,
  respawn/auxiliary state, input/movement, animation, active shots, cadence,
  and final counters in that sequence.
- `enemy_manager_update` runs `stage_timeline_step` before its per-enemy
  ECL/motion/state/player-shot-damage loop.
- `bullet_manager_update` first calls `item_manager_update`, clears six bullet
  spatial-bucket head arrays, scans all 1,536 hostile bullets for transform,
  motion, collision/graze, and cancellation, then scans lasers and advances
  final timers.

**Inferred from static order, pending runtime differential confirmation**:
playback input is available to same-frame player movement; items use the
post-movement player position; enemy-created active bullets can enter the later
same-frame bullet scan; cancellation-created items wait for the next item pass;
and a hostile hit established in priority 14 first reaches the priority-9
deathbomb transition on the following update.

`scripts/frame_schedule.py` is a game-neutral stable scheduler.
`scripts/th08_update_order.py` is the address-bearing TH08 adapter and keeps
live, legacy/extended playback, and recording modes separate.

## Item Runtime

**Observed** in `item_pool_spawn` (`0x004400A0`), `item_manager_update`
(`0x00440500`), and `player_test_item_collection` (`0x0044A5A0`):

- The pool has 2,096 records with stride `0x2E4`.
- The pool is embedded at the `g_item_manager` object base `0x01653648`; call
  sites load it with `mov ecx, offset g_item_manager`, so the first dword is not
  a manager pointer.
- Position begins at `+0x2A4`, velocity at `+0x2B0`, timer at `+0x2C8`, item
  type at `+0x2D4`, active byte at `+0x2D5`, motion state at `+0x2D7`, and
  full-value flag at `+0x2D8`.
- Free motion clamps vertical velocity to -2.2, moves by the character SHT
  fall scale and global time scale, and accelerates by 0.03 to a cap of 3.0.
- Homing sets velocity toward the player at SHT speed 10. It is enabled above
  y=128 when focused, at full power, or for stage-load indices 1/6. Player
  state 1/2 releases a homing item with vertical velocity -0.7.
- Route-2 item collection width is 24. The inclusive AABB test collects at
  center deltas `abs(dx) <= 24 && abs(dy) <= 24` in player states 0/3/4.
- Motion state 2 chooses target x in `[48,336)` and y in `[-64,128)` using two
  scaled RNG draws, then linearly interpolates from the spawn position for 60
  timer frames. At timer 60 it clears velocity, changes to state 0, and enters
  the generic fall pass in the same frame.
- Motion states 3/5 initialize `vy=-2-rng([0,0.2))` and
  `vx=rng([-1,1))*0.6`. Both add `0.05*time_scale` each frame. State 3 also
  takes the generic movement/acceleration pass but cannot be collected until
  it changes to homing. State 5 moves once, blocks collection while `vy<=0`,
  then changes to homing and takes a second generic movement pass on the
  transition frame.
- Type 0/2 add 1/8 power and convert active power items to type 8 on reaching
  full power. Type 1 applies the y-dependent point formula, type 3 increments
  Bomb stock up to 8, type 4 sets full power and awards 1000 score units, type
  5 awards a life or a Bomb at the life cap, type 6 awards scaled score, type 7
  mutates the time counters/point value, and type 8 awards one tenth of the
  point-item value. These are numeric type semantics; some conventional labels
  remain inferred.
- Point value is full only at `item_y < point_line` (strict) or with the
  full-value flag. Otherwise it is
  `base/2-int(y-line)*int(base/1000)`, truncated to a multiple of 10. Type 8
  divides candidate and comparison base by 10 before truncation.
- Point-item life/Bomb extend thresholds are `100,250,500,800,1100,9999`
  below difficulty 4 and `200,666,9999` at difficulty 4 or above.

## Player Damage And Bullet-Cancel Regions

**Observed**: the player object owns two contiguous arrays of 192 shared
64-byte region records:

| Player offset | Consumer | Purpose |
| ---: | --- | --- |
| `+0xB8834` | `player_compute_damage_to_enemy` (`0x00451670`) | damage |
| `+0xBB834` | `player_cancel_region_test_point` (`0x00449FF0`) | hostile-projectile cancel |

The four allocators at `0x0044DE60..0x0044E040` separately create cancel or
damage rectangles/circles. `player_projectile_pool_update` (`0x0044C5B0`)
updates all 384 records. Recovered common fields are:

| Offset | Meaning |
| ---: | --- |
| `+0x00/+0x04` | center x/y |
| `+0x08/+0x0C` | circle radius / radius delta |
| `+0x10/+0x14` | rectangle width / height |
| `+0x18/+0x1C` | width / height delta |
| `+0x20` | rectangle angle |
| `+0x24` | remaining frames |
| `+0x28` | cancel result code |
| `+0x2C` | damage per eligible check |
| `+0x30/+0x34` | accumulated damage / damage cap |
| `+0x38` | tick interval, initialized to 1 |
| `+0x3C/+0x3D` | active / suppress-hit-effect bytes |

Cancel circles test only the hostile projectile center and use strict
`distance_squared < radius_squared`; cancel rectangles include their boundary.
Damage circles also use the enemy center but include equality. Damage
rectangles overlap the enemy AABB, including boundaries. A positive damage cap
clips the final contribution exactly, then clears per-tick damage.

For Sakuya normal Bomb, 96 knives spawn in pairs at Bomb-local frames
`20,22,...,114`; each carries a radius-32 cancel circle (code 6) and radius-32
damage circle (20 damage). Her Last Spell uses 128 knives at
`20,22,...,146`, with damage 30. Both nominally allocate the regions for 500
frames, continuously move their centers with the knife, and explicitly release
them after the knife's local timer reaches 120 or after damage registers.

Remilia normal and Last Spell recreate a player-centered radius-96 cancel
circle every active callback frame and periodically add perpendicular
`96 x 800` / `800 x 96` cancel rectangles.

**Observed** in `player_emit_shot_level` (`0x00450F60`),
`player_shot_record_emit_if_due` (`0x0044FD80`), `player_shot_initialize`
(`0x0044FB70`), `player_update_shots` (`0x00451150`), and
`player_compute_damage_to_enemy` (`0x00451670`):

- When route ID 2 has an odd Bomb callback index and Bomb-local time has reached
  60, the secondary SHT is selected directly. Callback 1 (normal Remilia Bomb)
  selects `ply02as.sht` level 6; callback 3 (Remilia Last Spell) selects level 7.
- A live record fires exactly when `cadence_frame % fire_period == fire_phase`.
  This integer timer cycles over 0..19 while shot is held and is independent of
  Bomb-local time. Remilia Bomb damage therefore still requires shot input.
- `source_index=0` spawns at the player. Values 1..4 spawn at the corresponding
  option; record offsets are then added. Default velocity is
  `(cos(angle) * speed, sin(angle) * speed)`.
- Route 2 loads the same option update callback `0x0044EB70` and render callback
  `0x0044E9E0` into all four slots. On focus entry, the update callback captures
  the already-moved player position plus offsets `(-30,-16)`, `(-10,-32)`,
  `(10,-32)`, `(30,-16)`, then places each option on a radius-8 orbit. Initial
  angles are `0,pi,0,pi`; after integer timer `>12`, per-update deltas are
  `+1.5,-2,+2,-1.5` degrees. Focus release freezes the position in state 3 and
  clears it after timer `>16`.
- Player byte `+0x03` changes on the focus edge and immediately selects movement
  and primary/secondary SHT. Byte `+0x05` is a separate visual/character state
  that changes after the transition counter at `+0x08` reaches 7.
- Direction bits are decoded in native branch order `UL,DL,UR,DR,D,U,L,R`.
  Active Bomb state replaces the focus input with `callback_index & 1`.
  Movement then selects primary-unfocused or secondary-focused SHT speed,
  applies player x/y scales and global time scale, updates position, and clamps
  to the runtime playfield origin/extents.
- Level 6 has 16 cardinal records. Level 7 has the same 16 plus two
  player-sourced diagonals. All 34 records use type 6, base damage 45, speed 20,
  a 32 x 16 hitbox, and no custom callbacks.
- Ordinary-shot collision is an inclusive AABB overlap. While a Bomb is active,
  damage is divided by 5 with a minimum of 1, so each of these records
  contributes 9 per overlapping check. The 128-slot ordinary-shot subtotal is
  capped at 50 per enemy check. Type 6 skips the hit-state transition and keeps
  piercing.

These executable rules are in `scripts/th08_player_shot_model.py` and
`scripts/th08_option_model.py`; reusable movement geometry and the TH08 input
adapter are in `scripts/movement_model.py` and `scripts/th08_movement_model.py`.
Static order places option positioning inside input/movement before later
active-shot/cadence work and before priority-11 enemy damage. **Unknown**: full
runtime trace parity at focus/cadence/collision boundary frames.
